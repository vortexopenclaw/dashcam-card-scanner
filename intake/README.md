# Private Dashcam Card Scanner intake

Independent AGPL-3.0-or-later module. **Not deployed. No credentials included. No existing Offloader Worker/app files changed.** Node 22+ for review/tests; dependency-free Cloudflare ES-module Worker + Durable Object. `npm test` uses synthetic fixtures and mocked edge/Turnstile services, not real owner reports. Full license in LICENSE; preserve source notices and offer corresponding modified service source under AGPL section 13 when operated publicly. Upstream canonical profile snapshot retains its own provenance/license; private submissions and review state must NOT be included in public source distribution.

## App integration

Read **INTERFACE.md** first. Envelope/schema validator is `schema.js`; gateway is `worker.js`. Deliberately no legacy feedback endpoint compatibility. Adapter retains individual paired measurements, sanitized structural inventory and explicit owner labels; present exact JSON before sending, and discard private original paths/config/media identifiers. Completed positive-media structural scans may contribute with empty metadata evidence; never invent placeholder samples.

A report's SHA-256 binds a five-minute bearer ticket to the EXACT UTF-8 JSON bytes. The native app opens an isolated in-app verification window at `/challenge#app=1&hash=HASH&state=NATIVE_NONCE`; the page strips the initial fragment, runs real Turnstile, and receives a ticket via same-origin POST. A fixed same-origin `/app-complete#...` fragment navigation hands the ticket back to Rust; Rust cancels navigation, validates the current token/hash/window/nonce, and emits `verification-complete` only to the main app. The app POSTs the unchanged bytes to `/submit`, ticket in Authorization header only. No ticket in network URL/query, arbitrary callback target, remote application IPC, public read/list/delete, or public admin surface. The normal `/challenge#HASH` page retains manual fallback for compatible clients; current native submission requires its own session handoff. Browser CSP uses a per-response nonce and no external resources except Cloudflare Turnstile; user-controlled values render using textContent. No CORS permission is granted. See INTERFACE.md for event contracts, frame-policy limitations, Cloudflare WebView guidance, and the still-unproven live acceptance gate.

## Security and budget model

- Disabled/missing binding/salt/Turnstile/origin/quota configuration fails closed. All upload and challenge JSON is stream-counted (16 KiB/4 KiB), even absent/lying Content-Length. UTF-8 strict; unknown/nested fields, duplicate JSON keys, invalid enums and numbers rejected. Validation occurs BEFORE ticket redemption or private storage.
- Server verifies Turnstile success, exact configured hostname and `scanner_upload` action. Siteverify handles token replay; no raw IP is sent to siteverify. Tokens aren't logged. Real hostname/action/sitekey must be configured together.
- Cloudflare edge IP required for POST; only daily salted SHA256 fingerprints kept in bounded hourly control state. No raw IP in application state. Platform/network logs can still contain IPs: disable request/trace body and authorization logging; review Cloudflare's retention/privacy settings separately. Do not log exceptions/request objects or enable Logpush body/headers.
- One global DO name serializes transactionally: ticket issuance, expiry checks, single redemption, exact-byte dedup, record count and byte reservations. Tickets are stored hashed. Hash-correct schema-valid redemption consumes the ticket. Wrong hash does not consume it. Concurrent redemption gives one 202 and one 401. Expired tickets are pruned opportunistically, no background loops. Ticket bounded at 128 active; rate fingerprint entries at 256/hour; 10 attempts/IP/route/hour and 500 POST attempts globally/hour. All POSTs are charged before body/challenge work; no unbounded per-IP DO creation.
- Lifetime immutable record limit MUST be 1–10000 and lifetime JSON bytes budget 16384–100000000. Both include authoritative DO records and report/rawJSON wrapper accounting (not infrastructure overhead); private KV mirrors same records and roughly doubles payload storage. Duplicates do not increment stored quotas. Counters deliberately never reset automatically and do not decrease on local rejection. Quota exhaustion stops new records, still allows duplicate recovery. Setting `ENABLED=false` stops all intake. Do not casually rename/reset the DO or reuse old data with zero counters; migrate deliberately or create a wholly separate reviewed intake.
- DO record persists before KV mirror. A transient mirror failure consumes ticket but leaves authoritative record. Fresh challenge + same bytes reuses unchanged DO record and repairs KV. No automatic background publication. DO is inaccessible through public router; private KV values have no public route. All mirrors use exactly `pending/v1/SHA256`.
- **Not a guarantee against bots, spam, lies, or costs.** Turnstile can be solved/abused. Field semantics are user assertions: someone can put identifying text in a manufacturer/model label, and schema cannot detect every semantic misuse. Owner UI and maintainer review remain necessary. Anonymous submissions cannot prove distinct owners or independent observations; exact numeric hashes detect duplicate evidence, not independent corroboration. Global DO/Worker invocations and GET challenge requests incur cost even when rejected. Set Cloudflare edge rate rules/request caps, billing alerts and an emergency disable procedure before enabling; application quotas are not a hard account spend ceiling.

## Maintainer local review (CLI, no web server)

Private review state lives in `private/` (0700 dir /0600 created files) and is gitignored; keep on encrypted storage, don't sync publicly. Override with REVIEW_DATA_DIR if needed. No app or browser needs maintainer credentials.

```sh
npm test
node review.js snapshot
# Set these through your shell/secret manager; never paste tokens into commands/history:
# CF_ACCOUNT_ID, CF_KV_NAMESPACE_ID (both explicit 32-char lowercase hex)
# CF_API_TOKEN, OR CF_TOKEN_OP_REF=op://vault/item/field (op CLI required)
node review.js pull 5
# Result nextCursor can resume the next bounded page batch:
node review.js pull 5 'RETURNED_CURSOR'
node review.js review REPORT_SHA256
node review.js decide REPORT_SHA256 needs-info
node review.js decide REPORT_SHA256 accept
node review.js proposal REPORT_SHA256 > private/proposal.json
```

API token should have minimum read-only KV permissions for target account; Cloudflare token policy may only scope to account rather than namespace, so use a dedicated account/token where appropriate. Tool itself reads ONLY explicit namespace and `pending/v1/` prefix. Namespace ID has no default; other malformed keys ignored, fetched record ID/hash/envelope revalidated. API response bounded to 2 MB; 100 keys/page, 1–20 pages/call, resume cursor reported. Invalid, mismatched or oversized records are excluded from pending files, counted in `quarantined`, and marked under `pending/quarantine/HASH.json` (0600 files in a 0700 directory). Markers contain only key ID and fixed `invalid_record` reason, never unvalidated payloads or error text. Retrieval continues to later records/pages within the same bounds; repeated markers are not overwritten. Inspect these markers manually; re-pulling retries validation and never silently accepts damaged data. Network/auth/list failures still stop the pull. Existing local records never overwritten. Cloudflare KV listings are eventually consistent: re-pull from beginning later to find late keys. API errors deliberately suppress potentially secret-bearing response bodies. No remote writes from review CLI.

`snapshot` explicitly fetches GitHub repository HEAD, records exact commit/fetch date and all canonical profiles locally; subsequent review is offline. There is no implicit live lookup or automatic profile merge. Exact case/whitespace-normalized manufacturer+model matching only: ambiguous matches remain explicit; no fuzzy model invention. Display includes canonical evidence status, structured channel variants/parking modes and original technical facts for human comparison. Where upstream has `channel_variants`, compare declared channel count and a complete observed role set exactly; report known/new-layout candidate or insufficient observed channels. A known layout never implies matching firmware, quality, parking setting or bitrate.

`review` prints escaped JSON (safe in terminal, not HTML) containing every allowed field, sanitized raw report, assertions separately from scanner measurements, provenance hashes, firmware/quality/parking/channel-count/layout cohort, numeric evidence hash, duplicate evidence references (including different cohorts), possible same-cohort contradictions/variation and missing metadata. Conflicting settings/layouts are not conflated. New firmware/settings/layout/parking flags compare other local model submissions; no such claim is made against upstream when upstream doesn't have structured cohort data. Current canonical database has mixed textual `technical_facts` and heterogeneous metadata, so **automatic normalized numeric/cohort comparison against upstream is intentionally unavailable**; tool exposes that limitation and the source facts rather than fabricating comparisons. Maintainer must inspect source before accepting any claim.

Numeric hashes explicitly include channel, mode, codec and all measurement fields, excluding owner labels and positional folder references; size/duration pairs and repeated samples remain intact. Cohorts retain channel/mode relationships and case-sensitive folder identities, resolving references before order-independent comparison. Structural hashes normalize folder/layout/extension/template ordering without rewriting the immutable source report. Existing derived hashes may change; re-run review rather than treating old derived values as report-byte hashes. Report IDs still hash the exact original bytes.

`decide` appends accept/reject/needs-info/duplicate history in separate decisions.jsonl with record, evidence hash, timestamp and snapshot commit. Pending source stays immutable. No contact mechanism exists, so needs-info means awaiting voluntary richer resubmission, not automatic outreach. `proposal` requires latest local accept tied to the current nonempty snapshot commit; stale or missing snapshot linkage requires re-review and a fresh explicit accept. It prints explicitly unverified anonymous owner assertions/measurements with report/evidence/snapshot hashes, omits received timestamp/contact, and marks notPublished. Review semantic PII and contradictions manually before sharing proposal; this command never publishes, commits or modifies canonical profiles.

## Verification scope

Node tests cover fail-closed/public-access denial, challenge bypass/invalid origin/hostname/action, body/hash mismatch, expiry, replay and concurrent redemption, stream/header limits, field allowlist/numeric bounds/duplicate keys, rate/ticket/storage limits, immutable dedup, sanitized review/injection rejection, model/cohort comparisons, private namespace/prefix bounded pagination/resume and the actual CLI decision/proposal lifecycle. All card fixtures are explicitly synthetic. Real Cloudflare API credentials, real widget/browser, actual deployment, staging E2E and app adapter are not exercised here.

Audit regressions additionally exercise BOM rejection without ticket consumption, legacy corrupted-record quarantine and subsequent retrieval, positional-reference-independent measurement hashes, order-independent folder/mode cohorts, and stale-snapshot acceptance denial. `node test/run-auditor-repros.mjs` runs the two supplied sibling audit scripts when available, relocating all temporary state into this directory without changing the originals. Those exploit scripts assume successful vulnerable operations and now intentionally stop at their invalid success assumptions; the runner asserts the fixed outcomes and cleans its temporary files.
