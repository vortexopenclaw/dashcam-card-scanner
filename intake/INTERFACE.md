# Scanner intake v1 — revised pre-release contract

Executable authority: schema.js. No deployment.

## Additive private contributor / mixed-card contract (v1 pre-release)

Optional envelope `contributor:{dashcamTalkUsername}`: exactly one required string, 1..40 ASCII alphanumeric/space/dot/underscore/hyphen, beginning and ending alphanumeric (single alphanumeric allowed). No URLs, controls, notes or other fields. It is optional private maintainer contact, never identity verification. Omit entirely when unset. Private review retains it; ALL public proposals omit contributor and raw report/JSON. Public numeric/structure/cohort hashes exclude it; sourceReportHash remains exact-byte provenance, not a public link or raw-content export.

Optional `cohorts`: 1..16 objects, each exactly `{id,evidenceIndices,owner}` with optional `folderIndices`. `id` unique 1..32 ASCII alphanumeric/underscore/hyphen beginning alphanumeric. `evidenceIndices` unique valid zero-based sample indices (0..24 entries). Together cohorts MUST partition every evidence sample exactly once: no overlap or omitted samples. `folderIndices` unique valid zero-based structure folder indices (0..32 entries); these are context references, may be shared across cohorts, and MUST NOT be summed as separate inventory. Every cohort requires at least one evidence or folder reference. Structure-only reports require every folder referenced at least once. Owner requires `channelCount` 1..8; optional firmware/quality/parkingMode/timeLapseFps use the existing owner constraints. Manufacturer/model remain shared ONLY at envelope owner. Configuration fields never inherit from envelope owner when cohorts exist: missing per-cohort settings mean unknown. Shared owner channelCount remains required for legacy clients but is not a mixed-card setting. Observed sample channel/mode and numeric fields remain untouched; per-cohort owner settings are assertions, not measured facts. No free-text group labels.

Without cohorts, legacy one-configuration behavior is preserved. Review exposes `cohortReviews`, each with `id`, `evidenceIndices`, `folderIndices`, `ownerAssertions`, measurements, comparisons, flags and partition-independent numeric hash. Legacy top-level fields remain for compatibility; mixed-card comparisons/flags are derived separately per configuration. Canonical and prior-report comparisons do not merge configurations into one layout. Public proposals include sanitized cohort review data, never private contributor or raw report. Local API exports `listReports(dataDir)`, `reviewReport(dataDir,id)`, `decideReport(dataDir,id,decision)`, `createProposal(dataDir,id)`; CLI `list|review|decide|proposal` emits JSON for a native subprocess bridge, no server, shell interpolation, credentials in arguments or public listener. `list` returns an array of `{id,receivedAt,owner,contributor,cohortCount,decision}` (latest decision object or null). `review ID` adds `snapshotCommit` and `decisionHistory` to private review state. `decide ID accept|reject|needs-info|duplicate` emits the appended decision object plus a message; `proposal ID` emits the public allowlisted proposal or exits nonzero. Use explicit `REVIEW_DATA_DIR` environment, fixed script path, argument arrays and a native JSON parser, never evaluate subprocess JSON as code. All paths belong to private maintainer storage, not a public export directory.

Per-cohort measurement `folderIndex` references that cohort's `scannerReportedStructure.folders`; `folderIndices` maps these local positions back to original report folders. `evidenceIndices` always references original report samples. Original unmodified report evidence and structure remain at top level. Sampled cohorts use only their own measured channel/mode roles, never a shared folder's global roles. Structure-only groups use global folder roles only when the folder is not shared by another cohort; otherwise channel/config agreement is insufficient/manual. Shared folder inventory is context, not independent counts. Whole-report numeric duplicate detection ignores group boundaries; per-cohort comparisons identify matching prior `cohortId` and never establish settings agreement merely from equal numbers.

Envelope required `schemaVersion:1`, `owner`, `evidence`; optional `structure`. Owner channelCount integer 1..8; quality additionally `normal`; parkingMode additionally `low-power-impact`; optional positive finite `timeLapseFps` <=240 (owner cadence, never measured playback fps). Existing constrained labels remain; no notes.

Evidence is 0..24 INDIVIDUAL file samples, not averaged groups. Each requires channel, mode, width, height, fps, bitrateKbps, containerBitrateKbps, sizeBytes, durationSeconds, codec. Optional folderIndex references zero-based structure folder. No sampleCount/group metadata required or allowed. Channel adds telephoto; mode adds protected. Codec `h264|hevc|av1|mjpeg|mpeg4|unknown`. All numeric fields nullable when unknown: width/height positive integer <=16384, fps >0 <=240, video bitrateKbps and separately measured containerBitrateKbps >0 <=1000000, sizeBytes positive safe integer <=1000000000000, durationSeconds >0 <=86400. Never infer video stream bitrate from size/duration or container bitrate. Preserve exact individual size/duration pairs, never independently sort/average extrema. Unknown is null, not zero.

Structure requires completed:true, fileCount, mediaCount, folders, observedLayouts. Counts integer 0..10000000, positive mediaCount <=fileCount. Folders 1..32, immediate-parent totals sum exactly to structure totals. Each folder requires components (0..8, [] root), fileCount, mediaCount, extensions (0..16), filenameTemplates (0..16 unique). Unique component arrays. Extension entries {extension,mediaType,count}: positive integer counts sum to fileCount; video/image counts sum to mediaCount. Case-preserving extension matched case-insensitively: video mp4/mov/avi/ts/mkv; image jpg/jpeg/png; other dat/bin/txt/log/nmea/srt/unknown. Other extensions become exactly unknown.

Allowed components, case-insensitive matched with original case preserved: DCIM, Movie, Movies, RO, Parking, Photo, Photos, Video, Videos, Normal, Event, Events, Emergency, Record, Recording, Front, Rear, Interior, Telephoto, Left, Right, Lock, Locked, Snapshot, Snapshots, Continuous, Driving, BlackVue, INNOVV, Garmin, Thinkware, VIOFO. Unknowns become deterministic per-report folder-N (N=1..256), first-seen traversal order, reused for same original component. No alias lookup tables transmitted. Export sanitizeFolderComponents(components,map) uses caller-owned Map reused per report. No arbitrary paths/components, separators, traversal, original names.

Filename templates: finite stems YYYY_MMDD_HHMMSS_SEQUENCE, YYYYMMDD_HHMMSS, YYYYMMDD_HHMMSS_SEQUENCE, YYYY_MMDD_HHMMSS, SEQUENCE; optional suffix F/R/I/T/PF/PR/PI/PT directly or with underscore; dot plus known non-unknown extension preserving case. Example YYYY_MMDD_HHMMSS_SEQUENCET.MP4. Unknown shape exactly unknown, never original basename fragments. Export generalizeFilename fully matches known numeric families before replacement. observedLayouts: 0..64 unique {folderIndex,channel,mode}, valid references and sample enums, scanner observations not owner assertions.

Empty evidence is allowed ONLY for completed usable positive-media structure. Never fake metadata. Coverage reports insufficient measurements, not failed total scan. Whole JSON remains <=16384 UTF-8 bytes; if full bounded structural inventory cannot fit, keep local rather than falsely claim complete counts. Strict nested unknown-key rejection remains.

Review/proposal retain structure, paired measurements, owner assertions separately, report/evidence/structure hashes and canonical snapshot commit. Numeric duplicates exclude owner labels and positional folderIndex; they retain channel, mode, codec and every paired measurement. Raw samples retain location references separately. Cohorts preserve channel/mode/folder associations resolved to case-sensitive component arrays, independent of folder traversal order; structure hashes similarly normalize ordering without changing the retained report. Canonical folder comparisons use exact allowlisted structured paths only; aliases, filename regexes/unstructured claims remain manual (never execute upstream regexes). Complete observed channel sets compare structured variants only. No pattern match proves settings/numeric agreement. Proposal requires latest explicit local accept against the CURRENT snapshot commit; after a snapshot change, re-review and explicitly accept again. Never publishes.

## Private review decision details (local API)

`decideReport(dataDir,id,decision,details?)` accepts optional strict object `{note?,question?,reason?,reference?,cohortId?}`; each supplied text is a nonblank string <=2000 characters, without control characters except newline/tab. Unknown keys are rejected. `reference` is plain local text (existing report hash + cohort context or canonical profile ID + configuration context), never auto-opened or treated as proof. With details supplied, `needs-info` requires `question`; `duplicate` (GUI label “Mark as already covered…”) requires `reason` AND `reference`. Known model alone is not evidence of coverage. Legacy omitted details remain supported but make no coverage claim. Nothing messages a contributor: compose/store a specific private question and manually copy it to the optional DashcamTalk user.

Optional `cohortId` must identify a current cohort (`legacy` for old reports). It creates a private annotation ONLY, never report authorization or automatic filtering. Annotations appear in private `decisionHistory`, with details flattened on each entry. `listReports().decision` and proposal authorization use only the latest WHOLE-report entry (no cohortId). Cohort annotations do not override whole-report decisions, and whole-report accept still explicitly authorizes ALL cohorts against the current snapshot. No group is silently discarded as covered. Public proposals omit ALL decision history, questions, reasons, notes, references, contact and raw JSON. CLI supports `decide ID DECISION [DETAILS_JSON]` as one optional JSON argument, not a shell fragment. Native callers must use argument arrays; do not include secrets in details.

## Transport

Serialize ONCE as UTF-8 JSON without BOM. A leading UTF-8 BOM is explicitly rejected before ticket redemption or storage (HTTP 400); it is never silently stripped. Retain the exact bytes reviewed and approved by the user. Hash those bytes as lowercase SHA-256. No private original paths, filenames, configs, media, location, serial/device identifiers or unknown fields.



Example individual sample (synthetic):
```json
{"channel":"telephoto","mode":"normal","width":2560,"height":1440,"fps":30,"bitrateKbps":14000,"containerBitrateKbps":null,"sizeBytes":111149056,"durationSeconds":60,"codec":"h264"}
```

Labels: manufacturer/model 1–64 ASCII alphanumeric/space/dot/underscore/hyphen, beginning alphanumeric; optional firmware 1–32 same syntax. quality low/normal/medium/high/maximum/unknown. parkingMode off/buffered/time-lapse/low-bitrate/motion/impact/low-power-impact/unknown. Channel front/rear/interior/telephoto/left/right/unknown; mode normal/protected/parking/unknown. Owner labels remain unverified assertions. Omit unknown optional labels; never invent measurements.

1. Preferred native flow: user clicks Submit after reviewing the exact envelope; this action supplies submission consent. `begin_verification({token})` opens a transient, incognito remote webview at the compiled dedicated origin, `/challenge#app=1&hash=LOWERCASE_SHA256&state=NATIVE_RANDOM_64_HEX`. Fragment fields have fixed order and exact lowercase bounds; no arbitrary callback target is accepted. The page immediately clears the initial fragment with `history.replaceState`. It POSTs only `{hash,turnstile}` to `/ticket`; hostname/action validation and quotas are unchanged. On success it attempts `location.replace('/app-complete#state=...&hash=...&ticket=64lowerhex')`; on error the final field is `error=challenge` or `error=expired`. Native navigation interception cancels this request before navigation, checks exact origin/path/no query/credentials, nonce, window label, current reviewed token/hash and session lifetime, then emits only to `main`: `verification-complete` with `{token,ticket}`. The ticket is never displayed in app mode or sent in a request URL/query. The window closes. Listen before invoking begin; a challenge can complete before the command resolves.

   Failure contract: `verification-failed` with `{token,reason}`; reasons `cancelled`, `stale`, `expired`, `challenge`, `invalid_completion`. Opening errors reject the command (no event required). UI must ignore events for a different pending token, and call `cancel_verification({token})` on outgoing-data edits, source replacement or abandonment. Native review/source/scan changes also invalidate sessions. `submit_review({token,consent:true,ticket})` consumes the matching native approval before network I/O; even a failed upload needs fresh verification. Consent still must be explicit; it is the user's Submit action, not a checkbox or challenge callback.

   Browser fallback remains `/challenge#LOWERCASE_SHA256`, which displays the ticket for manual use by compatible clients. Current native submission deliberately requires a native handoff session rather than accepting pasted arbitrary tickets. Neither mode accepts callback URLs from callers.

   Remote webview has no capability entry, custom application commands are rejected unless originating from the `main` webview, popups/downloads are denied, and main CSP is unchanged. Navigation permits only intake `/challenge`, exact HTTPS `challenges.cloudflare.com` (Turnstile), and `about:blank`/`about:srcdoc`; completion is intercepted and never allowed. Tauri's current navigation callback does not expose main-frame versus iframe context, so these fixed Cloudflare/about exceptions also apply to top-level navigations. It cannot promise an intake-only top-level allowlist while preserving Turnstile iframe navigation with this API alone; a frame-aware native/runtime policy remains a hardening/acceptance limitation, not silently claimed as enforced.
2. App POST `/submit` with `Authorization: Bearer COPIED_TICKET`, `Content-Type: application/json`, body EXACT saved JSON bytes. Do not reserialize, append newline, or retry with modified payload. Limit 16384 bytes. Native HTTP client recommended; cross-origin browser submissions are not supported.
3. Success HTTP 202 `{ "id": "<report SHA256>", "status":"pending" }`. Duplicate exact bytes also accepted as duplicate without storing another report; response has `duplicate:true`. Errors return `{ "error": "..." }`; 400 invalid report/hash, 401 invalid/expired/replayed ticket, 403 challenge/origin failure, 413 body too large, 429 quota/rate limit, 503 disabled/unconfigured. Tickets valid 5 minutes, one redemption attempt for correct-hash/schema-valid payload; once redeemed never retry that ticket. Obtain fresh challenge if response lost. Report hashes deduplicate subsequent attempts.

Show the exact envelope locally before verification. Preserve the original richer scan locally only. The user's Submit action explicitly approves sending the displayed privacy-safe envelope; no separate consent checkbox is required. The compiled dedicated origin is `https://dashcam-card-scanner-intake.vortexradar.workers.dev`, never the Offloader feedback Worker. Configuration remains fail-closed.

### Webview support and live acceptance

Cloudflare's [WebView integration guidance](https://developers.cloudflare.com/turnstile/get-started/mobile-implementation/) explicitly describes embedded WebViews, including WKWebView. It requires JavaScript, DOM storage, standard web APIs, consistent default user-agent/environment, and access to the widget host plus `challenges.cloudflare.com`, `about:blank`, and `about:srcdoc`. It warns that restricted/nonpersistent cookie/storage behavior can fail challenges. This implementation does not alter the user-agent or spoof browser capabilities; incognito is intentional to keep challenge/ticket history off disk. This guidance is not a guarantee for this particular desktop Tauri build or incognito storage combination.

Required separate live gate: deploy the reviewed Worker change, open the packaged native app, complete a real Turnstile challenge in its transient window, observe automatic close and native exact-byte upload, and privately verify the stored pending record/hash and maintainer retrieval. Also exercise user close, outgoing-data edit, expiry, failed network, and popup/download/top-level navigation attempts. Until that gate is witnessed, real in-app verification/upload remains **unproven**. Unit tests use synthetic responses only; no production CAPTCHA is bypassed, no widget/secret settings are changed, and no deployment is performed by these changes.
