# Reviewed private media identity retention

This supersedes older claims that *all* Scanner exports/intake omit basenames. The anonymous public schema export is unchanged; the detailed private export and explicitly approved private intake retain bounded source identity.

- Each retained safe video/photo sample has `sourceIdentifier`, unchanged `filename`, and relative `folder` directly beside its measurements and native channel/mode hints. `folderIndex` must resolve to that same folder. Identical basenames in different folders remain distinct. Keys are opaque `source-N` positions from sorted retained native identities, not hashes of names, paths or serials. They are payload-local, not cross-scan IDs.
- Native `local_name` stays skipped in general report serialization/deserialization. Only the explicit private-envelope adapter copies it. Basename safety accepts new camera grammars using structural bounds and supported media extensions; it never repairs unsafe names or invents a link to independent numeric extrema. Photos retain size and identity without manufactured video metadata. Native source opening, symlink rejection and disabled OCR are unchanged.
- Relative known camera-folder tokens are retained; unrelated components use the existing consistent folder aliases. Absolute source paths, traversal, control/bidi characters, config/GPS contents and unrelated support files are excluded. Private names may disclose dates. The visible Submit disclosure explicitly describes this, and scanning alone never sends data. The review shows names alongside each retained pair and exposes exact outgoing JSON before voluntary submission.
- Native representative storage remains at 64 rows and outgoing evidence at 24 rows / 16 KiB. Small cards retain every media sample that fits those limits, instead of silently taking only two samples per encoding stratum. At the native cap, late new strata reclaim redundant rows and linked bitrate/duration extrema replace redundant same-stratum rows. Outgoing over-budget selection prioritizes extrema within template families and round-robins families/folders. Whole-card metadata coverage remains independent of representative retention.
- Optional `retention` has exactly `inventoriedIdentities`, `retainedIdentities`, `omittedIdentities`, `measuredFiles`, `retainedMeasurements`, and `omittedMeasurements`. Nonnegative bounded counts reconcile with media totals and actual outgoing linked/measured rows. Inventoried identities include unsafe/unretained media; omitted identities include those safety/budget omissions. Measured rows with unsafe names can preserve anonymous numbers without retaining unsafe identifiers. Completed positive-media structural scans and older envelopes without identities/counts remain accepted.
- The actual gateway uses strict validation as its no-normalization sanitizer: accepted private report objects and frozen UTF-8 bytes are stored unchanged. Unknown/partial identity triples, duplicate source keys, duplicate folder/name pairs, folder mismatches and inconsistent counts are rejected. No submission to production is required or performed by offline tests.
- The detailed local export uses the actual private evidence envelope (without optional contributor), not the legacy anonymous feedback template. When an incomplete/oversized structure prevents intake, the local detailed fallback preserves the same bounded rows and counts as `privateEvidence` / `privateRetention` alongside anonymous aggregate history. Grouped owner settings remain separate from native observations. Accepted-only public proposals recursively remove original filenames, source keys and private folder fields, consistently anonymize component identities, and retain exact anonymous numeric pairs/channel/mode. Public schema exports continue to contain aggregate summaries rather than unsupported extra properties.

`tests/private-identities.test.js` exercises actual generated BMFF inventory/header probing, native prepared review, strict receiver validation, real Worker handler with transactional mock storage, exact KV and authoritative record readback, immutable local review/accept/proposal, legacy/safety negatives, photos, duplicate basenames, per-row channel/mode, and 70-file native omission/late-short-outlier coverage with source hash/mtime readback. All committed media-name examples are synthetic 2030 fixtures. This proves local contract behavior, not deployed compatibility or physical-card results. Deploying a compatible intake is a separate parent-controlled gate before distributing the changed client. Existing stripped receipts cannot recover names retroactively.
