# Optional temporal persistence (source integration only)

The intake v1 envelope optionally retains `temporalEvidence` v1. Native preparation derives it exclusively from the native report inventory and native recognition; owner model labels and renderer statistics do not supply authority. Cohorts are anonymous, parking-first, capped at eight with explicit total/omission counts. All floating statistics are finite bounded numbers or null. Incomplete/capped or fewer-than-four-pair cohorts have no cadence or family recommendation. The existing 16 KiB limit and all selected paired measurements remain intact: optional summary rows shrink first, then the optional field is omitted with a local warning if necessary. Group annotation/contributor additions apply the same policy.

`Labels.suggestedFields` and group `owner.suggestedFields` accept unique `parkingMode`/`timeLapseFps` entries (default absent/empty for legacy clients). The UI owner must pass these for untouched auto-populated values, clearing each only on explicit user edit. Submit alone must not clear them. Group settings are independent, never inherited by the native adapter. Public/legacy notes identify automatic estimates; review and accepted proposal expose them separately as `estimatedSettings`, not `ownerAssertions`. Private/proposal `derivedTemporalEvidence` remains unconfirmed and separate from measured playback fps. Settings and provenance are untrusted assertions, not authentication.

The offline `intake/test/temporal.test.js` runs the actual Rust serializer over generated metadata-only BMFF media, validates strict schema, submits to the real Worker handler with transactional in-memory storage, reads exact stored bytes back, and exercises accepted proposal retention. It does not deploy or prove production retention. Deploy and verify the compatible Worker before an app may claim remote retention of these new fields; this lane performs no deployment, release, authentication, or owner-media access.
